## 04-2 review saga — READ THIS, it carries the key lesson

PR #46 took **5 Codex rounds**, and Codex found a legitimate P1 **every single
round** — all instances of ONE defect class:

> **Invariant:** the §4.2 holdout guard must validate every concrete date range
> whose data is *actually read* during dispatch (inclusive boundaries) — never a
> declared/base range that dispatch can silently diverge from.

Instances, in order: R2 base range not constrained to `[train_start, oos_end]`
(post-holdout leak); R3 inclusive boundary + schema-permitted `oos_end ==
holdout_start` (needs `effective_end < holdout_start`); R4 sweep `param_grid`
overriding `backtest.start_date`/`end_date` per variant; **R5 sweep `param_grid`
key of `backtest` (whole section) replacing the mapping incl. the dates** —
which the R4 fix's *exact-leaf-key* filter missed.

**The lesson (operator-driven, and the crux of this handoff):** the R4 fix was an
instance patch (reject two exact keys), so R5 found the same class one level up.
The correct fix is the **GENERAL semantic rule**, landed in `903a752`:
`run_parameter_sweep` rejects any `param_grid` key whose **dot-path is an
ancestor-or-equal** of either window leaf (`backtest.start_date`/`end_date`) —
catching `backtest`, root/empty keys, and the leaves, while still allowing
sibling `backtest.initial_capital`. When you fix a defect *class*, implement the
invariant once as a general rule; do not patch the cited instance and re-summon.
(This is the second time this exact "sweep by code-shape, not by invariant"
mistake recurred this round — see `rqis-r2-pm-workflow` memory.)

The class is now closed at the mechanism level: (a) ancestry-based reject of
window-moving sweep overrides — audited against `config_contract._BACKTEST_FIELDS`,
where `start_date`/`end_date` are provably the only two consumed keys that move
which dates' data is read; (b) per-variant re-validation by the 02B contract, so
a variant can't introduce a new key; (c) an explicit assertion in
`WalkForwardValidator.run` that folds stay within the validated outer range;
(d) R2/R3 containment + strict boundary.

## How this round runs (conventions — follow these)

- **Structure:** PM orchestrates Sonnet 5 (medium) builders. Each roadmap job →
  one PR into `dev/R2-phase1`; each phased slice → one commit. **Operator merges;
  PM never merges.** Task branches `dev/R2-<order>-<slug>`.
- **Per-slice flow:** builder builds → PM reviews the diff (independently, re-run
  the suite) → **adversarial reviewer** (execute-the-attack) → fix round → builder
  opens PR → **Codex babysit** (poll all three comment surfaces via `gh api
  --paginate`, ~2-min cadence, substring-match `codex`; a round = a real submitted
  review with an intervening re-summon; stop at **two consecutive rounds with no
  new P0/P1**; **4-round cap** then escalate to operator). See
  `pr-babysit-api-levels`.
- **Commit trailers (hook-enforced, and the hook also requires a descriptive
  BODY, not just title+trailers):** `AI-Agent: Claude <model-id>` +
  `Chat Session ID: <uuid>`.
- **Codex is LIVE** on this repo (responds in ~3-6 min). Do not assume the waiver.

## Division of labor (operator-corrected TWICE this round — get this right)

- **PM owns:** GitHub polling (a `run_in_background` bash `for`-loop over `gh api
  .../reviews` for a `submitted_at` newer than the summon — foreground `sleep` is
  blocked); re-summoning; reviewing; the stop condition.
- **Builders own substantial fixes/builds** — dispatched with a BOUNDED,
  no-waiting task ("build → run pytest in ONE foreground call → commit → push →
  report; do NOT background pytest, do NOT arm a Monitor, do NOT babysit").
- **BUT the PM OWNS small, precise, general-rule fixes** — do not delegate a
  subtle class-closing fix as a narrow instance patch (operator: *"don't delegate
  the precise fix. Own the fix yourself, and fix the GENERAL rule."*). Delegating
  narrow patches is what let the holdout-leak class reopen round after round.
