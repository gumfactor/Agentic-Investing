## Gotchas that bit this session (save yourself the pain)

- **Builder agents keep stalling** on the 600s no-progress watchdog when they
  (a) background their pytest run / wait on a Monitor, or (b) hit a natural
  pause. Instruct every builder and reviewer: **run pytest synchronously in the
  foreground** (one blocking Bash call, ~3 min is fine), never backgrounded,
  never via Monitor. Tell builders to **push before running the suite** so work
  is never stranded.
- **Never trust a builder's "green" report** — verify yourself. Multiple
  builders reported success while the branch was unpushed, had uncommitted
  changes, or had a real regression (03A-1 regressed 13 safety tests; 03B left
  its isolation fix uncommitted). PM ran the full suite independently every time
  and caught each. Recovering a stalled builder's correct-but-uncommitted work
  as a PM leftover commit is fine and faster than a round-trip.
- **PR serialization on `bugs.md`:** every slice edits `bugs.md`, so only ONE
  PR open at a time even when code is disjoint. Parallel BUILDS are fine;
  serialize at the PR stage. Rebase the next branch after each merge.
- **Bug-number collisions** happen when parallel branches both pick the next
  number (03B and 03A-4a both grabbed BUG-078). Assign numbers centrally or
  reconcile at rebase. Current highest: **BUG-081**.
- **Paper-path tests are flaky** under full-suite order (env/cwd pollution +
  wall-clock `date.today()` guards). BUG-081 fixes the class; until then, a
  single full-suite failure in `tests/test_paper_*` that passes in isolation is
  almost always this, not a regression — but verify (isolation run + re-run).
